## Context

The group runs 3 travel products. Rail Ninja sells train tickets, Firebird Tours sells tours, and Triptile helps people plan a trip. Each one has a website and an app. About 20 developers and 5 designers worked on them.

## Problem

Every mockup was drawn from scratch. Developers had it worse: they built the same date picker again for each product. A designer couldn’t help out on another product, because each one was put together differently. And reviews kept turning into debates about colours and spacing.

## What I did

- **Pitch.** Took the idea to the design lead first, then to the managers and the founder, and got it approved.
- **Tokens.** Colour, type, spacing and radius, with a theme for each brand. A component picks up a brand’s look when you switch the theme, so nobody has to redraw it.
- **Components.** Buttons, inputs, calendars, the search bar, the traveller selector and the rest: 2,000+ components and variants. Each one has default, hover, focus, filled, error and disabled states.
- **Documentation.** Usage rules for every component in Confluence, so designers and developers read the same page.
- **Rollout.** Before a component went to production, I presented it to analysts, managers, developers and designers. I also set up a new way to structure, store and hand off design files.
- **Upkeep.** Designers brought me new cases, and I added to the components as they came up.
